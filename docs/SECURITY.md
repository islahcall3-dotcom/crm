# وثيقة الأمان (SECURITY.md)

## 1. نموذج التهديدات (Threat Model) المختصر
- **الأصول (Assets):** بيانات العملاء (أسماء، هواتف، عناوين)، سجلات الصيانة، الجلسات.
- **المهاجمون (Threat Actors):** زوار غير مصرح لهم، مستخدمون داخليون يحاولون تخطي صلاحياتهم، مهاجمون خارجيون (عبر XSS أو SQL Injection).
- **أهم التهديدات وتخفيفها:**
  1. **تسريب بيانات العملاء عبر الـ API:** تطبيق فحص الصلاحيات (RBAC) الصارم على كل مسار (Deny-by-default).
  2. **سرقة الجلسات (Session Hijacking):** استخدام Cookies محمية بخصائص `__Host-`, `HttpOnly`, `Secure`, `SameSite=Lax`.
  3. **هجمات CSRF:** استخدام نمط Double-Submit Cookie + فحص صارم للـ `Origin` و `Referer` على الطلبات المعدلة.
  4. **حقن SQL:** استخدام Drizzle ORM الذي يقوم بـ Parameterization تلقائياً لكل المدخلات.
  5. **الثغرات عبر متصفح العميل (XSS):** تفعيل سياسة CSP صارمة تمنع `inline-scripts`، وتطهير البيانات في الـ Frontend عبر React (الذي يحمي من XSS افتراضياً).

## 2. إدارة الجلسات (Sessions)
- لا يتم استخدام JWT بسبب صعوبة إبطالها الفوري في حالة سرقة الحساب.
- يتم توليد رمز عشوائي قوي (256-bit) عند تسجيل الدخول، يُخزّن كـ Hash (SHA-256) في قاعدة البيانات.
- الجلسة تنتهي (Idle timeout) بعد 8 ساعات من الخمول، وتنقضي تماماً (Absolute timeout) بعد 7 أيام.
- الإبطال الفوري: يتم طرد المستخدم من جميع الأجهزة عند تغيير كلمة السر أو عند سحب الصلاحيات من قبل الإدارة.

## 3. حدود المعدل (Rate Limiting)
نظراً لأن المشروع قد ينشر على `Cloud Run` متعدد النسخ، سيتم تخزين عدادات الـ Rate Limiting في قاعدة البيانات (PostgreSQL) لمنع هجمات Brute-force على مسار تسجيل الدخول (حسب الـ IP واسم المستخدم).

## 4. الحماية المتقدمة (Headers & CSP)
سيتم تفعيل الـ Headers التالية:
- `Strict-Transport-Security (HSTS)`
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Content-Security-Policy`: صارمة، تمنع تحميل أي موارد خارجية إلا من مصادر موثوقة ومحددة، وتمنع `unsafe-inline`.

## 5. الأسرار وكلمات المرور
- **كلمات المرور:** ستخزن كمخرجات تشفير `Argon2id` (أفضل المعايير الحالية للـ Password Hashing).
- **الأسرار (Secrets):** ستحقن كمتغيرات بيئة ولن يتم رفعها لـ Git بأي شكل. في مرحلة الإنتاج ستستخدم خدمة `Secret Manager`.

## 6. آلية إنشاء أول مدير (Bootstrap)
- لتجنب وجود حسابات ثابتة بكلمات مرور افتراضية مثل `admin/admin123`، سيوفر النظام أمر سطر أوامر `npm run bootstrap:admin`.
- سيطلب الأمر كلمة المرور تفاعلياً، ولن يطبعها في السجلات. يعمل هذا الأمر مرة واحدة فقط إذا لم يكن هناك أي مدير مسجل.

## 7. سياسة الـ Audit (سجل العمليات)
- أي طلب HTTP يؤدي إلى تغيير (POST, PUT, PATCH, DELETE) يجب أن يُسجل في جدول `audit_logs`.
- السجل يشمل: (من قام بالعمل، متى، الجدول المعدل، الإجراء، والبيانات القديمة والجديدة) لضمان المساءلة الكاملة.
